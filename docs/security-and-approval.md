# Security and approval boundaries

Zero remains the sole final authority. Planner/worker/reviewer output proposes files; native `fs_stage` binds exact contents, root, project, task, run, revision, expiry and one-time authority. Telegram checks the paired numeric user and allowed chat for every callback. Agent identities, names, model text, MCP output, personality and replay cannot authorize themselves. High-risk Telegram approval records intent and still requires native desktop confirmation. No approval is inferred from silence or elapsed time. Restart revokes transient approval authority.

All file operations retain canonical approved-root, relative-path, traversal and symlink checks. CLI inference works in fresh UUID scratch directories with shell/write/read/web/MCP tools denied; Cursor's approved trust flag applies only to that scratch directory. Cancellation kills child process trees. No renderer or Telegram command accepts an arbitrary executable or shell string. Two simultaneous project runs require distinct approved roots; FIFO per-provider queues keep one active call/provider. Streaming output is staged in memory and is not project-file authority. Durable flight records recover interrupted work as stopped, never auto-replay tools or approval.

The scoped registry lists actual native read/stage/apply/check/capture/Telegram capabilities and their boundaries. No external MCP server or schemas have been verified for this workspace, so external MCP execution stays **Manual/Disabled**. There is no invented connect/install success. Use the existing bounded native tools until a specific connector, schema, cost class and project scope are approved. Tool output cannot alter permission policy. Live trading remains prohibited; TradeAI is paper research only.

Telegram credentials and DeepSeek keys remain in the OS vault, not persisted frontend state. DeepSeek uses native masked entry and no environment fallback. Generic external inference is prohibited. Capture is limited to the own Swarm window with per-use consent, visible status and stop. Import/sharing requires native owner selection and approval of a scoped artifact. Secret/code screening is conservative and is not a substitute for inspecting approved media before sharing.
